# Resumen Clase 02 - HTTP

Resumen orientado a resolver la **Guía 02 de ejercicios**.

---

## 1. Evolución de HTTP

| Versión | Año | Características clave |
|---|---|---|
| **HTTP 0.9** | 1991 | Solo GET, texto plano, sin headers, sin estado |
| **HTTP 1.0** | 1996 | GET/POST/HEAD, códigos de estado, MIME, una conexión por recurso |
| **HTTP 1.1** | 1999 | Headers, PUT/DELETE/TRACE/OPTIONS, conexiones persistentes, cache, negociación de contenido |
| **HTTP/2** | 2015 | Protocolo binario, compresión de headers, multiplexación, server push |

> [!important]
> HTTP es **stateless** (no mantiene estado). Las cookies son el mecanismo para simular estado entre cliente y servidor.

## 2. URI / URL / URN

**URI** (Uniform Resource Identifier) es el concepto general que abarca URL y URN.

### URL (Uniform Resource Locator)

Identifica un recurso **por su ubicación**.

```
<scheme>://<user>:<password>@<host>:<port>/<path>?<query>#<fragment>
```

- El path termina con el primer `?` o `#`
- El puerto es opcional si es el default (80 para HTTP, 443 para HTTPS)
- Puede ser relativo o absoluto

### URN (Uniform Resource Name)

Identifica un recurso **por su nombre**. No implica que exista ni cómo acceder a él.

```
urn:isbn:0132856204
```

## 3. Métodos HTTP

### Request (cliente -> servidor)

| Método | Descripción |
|---|---|
| **GET** | Solicita un recurso |
| **HEAD** | Solo los headers del recurso (sin body) |
| **POST** | Envía información al servidor para ser procesada |
| **PUT** | Envía un recurso al servidor |
| **DELETE** | Elimina un recurso |
| **OPTIONS** | Consulta métodos disponibles |
| **TRACE** | Analiza el recorrido de la solicitud |

### GET vs POST

| | GET | POST |
|---|---|---|
| **Cache** | Sí | No |
| **Historial** | Sí | No |
| **Bookmark** | Sí | No |
| **Longitud** | Acotada | Sin restricción |
| **Uso** | Solo pedir datos | Enviar datos |

### Response (servidor -> cliente)

| Código | Significado |
|---|---|
| **1XX** | Información - el proceso continúa |
| **2XX** | Éxito |
| **3XX** | Redirección |
| **4XX** | Error en el cliente |
| **5XX** | Error en el servidor |

## 4. Estructura de un mensaje HTTP

### Request

```
GET / HTTP/1.1                    ← Start line (método, recurso, versión)
Host: www.ejemplo.com             ← Headers
User-Agent: Mozilla/5.0
Accept: text/html
                                  ← Línea en blanco
(body, solo en POST/PUT)
```

### Response

```
HTTP/1.1 200 OK                  ← Start line (versión, código, mensaje)
Content-Type: text/html           ← Headers
Content-Length: 24495
                                  ← Línea en blanco
<html>...</html>                  ← Body
```

> [!important]
> Los headers y la start line son **solo US-ASCII**. El body puede contener cualquier tipo de contenido gracias a **MIME**.

## 5. Headers HTTP

**Tipos** (en orden usual de envío):

1. **Generales**: Cache-Control, Connection, Date, Transfer-Encoding, Via
2. **De solicitud**: Accept, Accept-Language, Host, User-Agent, Referer, If-Modified-Since, Range
3. **De respuesta**: Age, Connection, Location, Server, Retry-After, Authorization
4. **De contenido**: Content-Type, Content-Length, Content-Encoding, Expires, Last-Modified

---

## 6. Conexiones HTTP

- **No persistente** (HTTP 1.0): una conexión TCP por cada recurso → conectar, pedir, recibir, cerrar
- **Persistente** (HTTP 1.1): múltiples recursos sobre la misma conexión TCP → pipelining

---

## 7. Tipos de contenido (MIME)

Cada recurso es etiquetado con su tipo MIME: `text/html`, `image/jpeg`, `application/pdf`, `video/mp4`, etc.

---

## 8. Proxy Servers

Un **proxy** actúa como intermediario entre cliente y servidor web. Puede ser **explícito** o **transparente**.

### Forward Proxy (del lado del cliente)
- Controla acceso a sitios
- Almacena en caché consultas recientes
- Filtra contenido

### Reverse Proxy (del lado del servidor)
- Balancea carga entre servidores internos
- Una única IP pública para múltiples servidores internos

---

## 9. Cache HTTP

### Sin directivas
Cada request se reenvía al servidor (sin cachear).

### Con `Cache-Control: max-age=N`
El proxy cachea la respuesta por N segundos. Agrega header `Age` en respuestas cacheadas.

### Con `Last-Modified` + `ETag`
El proxy revalida con el servidor usando `If-Modified-Since` y `If-None-Match`. Si no cambió, el servidor responde **304 Not Modified** (sin body).

### Combinando ambos
Primero se usa `max-age` para servir desde cache. Cuando expira, se revalida con `Last-Modified`/`ETag`.

## 10. Cookies

- Texto enviado por el servidor y almacenado por el browser
- Mantienen estado entre cliente y servidor
- **Set-Cookie** (response header): servidor → cliente
- **Cookie** (request header): cliente → servidor

### Tipos
- **Session cookie**: vive hasta cerrar el browser
- **Persistent cookie**: tiene fecha de expiración
- **Third-party cookie**: de otro dominio
- **Secure cookie**: solo se envía por HTTPS
