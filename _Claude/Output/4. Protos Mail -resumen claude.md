# Resumen Clase 04 - Mail y SSL/TLS

Resumen orientado a resolver la **Guía 04 de ejercicios**.

---

## 1. Correo Electrónico - Componentes

| Componente | Función |
|---|---|
| **MTA** (Mail Transfer Agent) | Transfiere mensajes entre hosts (ej: Postfix) |
| **MUA** (Mail User Agent) | Permite al usuario leer y enviar mensajes (ej: Thunderbird) |
| **MDA** (Mail Delivery Agent) | Coloca el mensaje en la casilla de correo (ej: Dovecot) |

En Unix/Linux, cada cuenta de usuario tiene una casilla de mail en `/var/spool/mail/usuario`.

---

## 2. SMTP (Simple Mail Transport Protocol)

- **Puerto 25** (TCP)
- RFC 821 (1982), RFC 5321 (2008)
- Transferencia directa: sending server → receiving server
- Mensajes en **US-ASCII (7 bits)**
- Interacción comando/respuesta

### Fases
1. **Handshaking** (HELO/EHLO)
2. **Transferencia de mensajes**
3. **Cierre**

### Transacción SMTP

```
S: MAIL FROM:<smith@alpha.arpa>
R: 250 OK
S: RCPT TO:<jones@beta.arpa>
R: 250 OK
S: RCPT TO:<green@beta.arpa>
R: 550 No such user here
S: DATA
R: 354 Start mail input; end with <CRLF>.<CRLF>
S: Blah blah blah...
S: <CRLF>.<CRLF>
R: 250 OK
```

### Undeliverable mail
Se envía con `MAIL FROM:<>` (remitente vacío) para evitar loops.

### Extensiones
- **ESMTP** (RFC 1869, 1995)
- **SMTP AUTH** (RFC 2554, 1999)

## 3. Protocolos de entrega final a usuario

### POP3 (Post Office Protocol) - Puerto 110

- Obtiene mensajes del servidor y los almacena en el host local
- Fases: **autorización** (USER/PASS) y **transacciones** (LIST/RETR/DELE/QUIT)
- Respuestas: `+OK` o `-ERR`

| Comando | Función |
|---|---|
| USER / PASS | Autenticación |
| STAT | Cantidad de mensajes y bytes |
| LIST | Listar mensajes |
| RETR n | Obtener mensaje n |
| DELE n | Marcar para borrar |
| TOP msg lines | Header y primeras líneas |
| QUIT | Cerrar conexión |

### IMAP (Interactive Mail Access Protocol) - Puerto 143

- Pensado para consultar correo desde **varios hosts**
- Almacenamiento **central** en el servidor
- Distingue mensajes leídos/no leídos
- Permite crear **carpetas** en el servidor
- El servidor realiza backups

| Comando | Función |
|---|---|
| LOGIN user key | Autenticación |
| SELECT mailbox | Seleccionar buzón |
| FETCH n mbx | Mostrar mensaje |
| CREATE / DELETE / RENAME | Gestión de buzones |
| CLOSE / EXPUNGE | Cierre y borrado |

### Webmail
Cliente MUA con interfaz web. Se comunica por HTTP con un servidor que usa POP/IMAP/SMTP internamente.

## 4. Formato de un mensaje (RFC 822)

1. Envoltura (RFC 821)
2. Campos de cabecera (From, To, Subject, etc.)
3. Línea en blanco
4. Cuerpo del mensaje

> [!important]
> SMTP y RFC 822 se limitan a **texto ASCII de 7 bits** con longitud de línea máxima de 100 caracteres.

---

## 5. MIME (Multipurpose Internet Mail Extensions)

Agrega estructura al body del mensaje para permitir contenido no-ASCII. Es **transparente para SMTP**.

### Headers MIME
- `MIME-Version: 1.0`
- `Content-Type: type/subtype`
- `Content-Transfer-Encoding: base64 | 7bit | 8bit`

### Content-Type

| Type | Subtype |
|---|---|
| text | html, plain, richtext |
| multipart | mixed, alternative |
| image | gif, jpeg, tiff |
| video | mpeg, quicktime |
| audio | basic, x-wav |
| application | pdf, rtf, postscript |

## 6. Base64

Codificación para enviar datos binarios sobre canales de 7 bits.

### Algoritmo
1. Tomar **3 bytes** (24 bits)
2. Dividir en **4 grupos de 6 bits**
3. Cada grupo (0-63) se mapea a un carácter del alfabeto Base64 (A-Z, a-z, 0-9, +, /)
4. Si los bits no son múltiplo de 6, se agregan ceros y caracteres de relleno `=`

### Ejemplo
```
3 bytes: 10101111 11001010 11101010
Grupos:  101011  111100  101011  101010
Decimal:    43      60      43      42
Base64:      r       8       r       q
```

> [!note]
> Base64 incrementa el tamaño del mensaje en ~33% (3 bytes → 4 bytes).

## 7. SPAM y defensas

### Defensas
- **Deny/Allow lists**: listas de IPs bloqueadas/permitidas
- **GreyListing**: rechazar temporalmente y aceptar en el reintento
- **Filtros Bayesianos**: clasificación probabilística

### Autenticación de mails

**SPF** (Sender Policy Framework):
- Registro TXT/SPF en DNS que lista IPs autorizadas a enviar mail del dominio
- El receptor consulta DNS del remitente para verificar

**DKIM** (DomainKeys Identified Mail):
- El servidor firma el mail con su **clave privada**
- La **clave pública** se publica en DNS
- El receptor verifica la firma descargando la clave pública

## 8. SSL / TLS

### SSL (Secure Sockets Layer)
- Desarrollado por Netscape (1994)
- Capa intermedia entre aplicación y TCP
- Permite autenticación mutua y encriptación

### TLS (Transport Layer Security)
- TLS 1.0 basado en SSL 3.0
- Conexión segura por **puerto**: 443 (HTTPS), 993 (IMAPs), 995 (POPs)
- Conexión segura por **protocolo**: STARTTLS

### Criptografía

**Clave simétrica**: misma clave para encriptar y desencriptar. Rápida.

**Clave asimétrica** (pública/privada):
- Mensaje cifrado con clave pública → solo se descifra con clave privada
- Mensaje cifrado con clave privada → solo se descifra con clave pública (firma digital)

### SSL Handshake
1. Cliente solicita conexión segura (HTTPS)
2. Servidor envía **certificado X.509** con su clave pública
3. Cliente verifica autenticidad del certificado (contra CAs conocidas)
4. Cliente genera **clave simétrica aleatoria** y la encripta con la clave pública del servidor
5. Ambos usan la clave simétrica para encriptar la sesión

### Certificados
Incluyen: clave pública, datos de la autoridad, período de vigencia, firma digital del emisor (CA).

### DNS seguro
- **DoT** (DNS over TLS): puerto 853, nativo en algunos Linux
- **DoH** (DNS over HTTPS): RFC 8484, configurado en el browser

### HTTPS y Proxies
- Con HTTP: el proxy puede inspeccionar y cachear contenido
- Con HTTPS: el tráfico está cifrado, el proxy no puede ver el contenido
- **MITM**: el proxy genera certificado falso (requiere que el cliente confíe en el CA del proxy)
- **Sin MITM**: se puede filtrar analizando **SNI**, DNS o listas de IPs
