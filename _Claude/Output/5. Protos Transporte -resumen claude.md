# Resumen Clase 05 - Transporte

Resumen orientado a resolver la **Guía 05 de ejercicios**.

---

## 1. Capa de Transporte - Servicios

Provee comunicación **lógica** entre dos procesos que corren en distintos hosts.

- **Emisor**: separa mensajes en **segmentos** y los entrega a capa de red
- **Receptor**: reensambla segmentos en mensajes y los pasa a la aplicación

| Servicio | TCP | UDP | SCTP |
|---|---|---|---|
| Control de congestión | Sí | No | Sí |
| Control de flujo | Sí | No | Sí |
| Establecimiento de conexión | Sí | No | Sí |
| Confiabilidad | Sí | No | Sí |
| Garantía de latencia mínima | No | No | No |
| Garantía de ancho de banda | No | No | No |

---

## 2. Multiplexación / Demultiplexación

### Puertos (RFC 1700)

| Rango | Uso |
|---|---|
| < 255 | Aplicaciones públicas (HTTP=80, SMTP=25, DNS=53, etc.) |
| 255-1023 | Asignados a empresas |
| > 1023 | No regulados |

### Demultiplexación sin conexión (UDP)

Socket identificado por `<IP destino, Puerto destino>`. Datagramas de distinto IP origen van al **mismo socket**.

### Demultiplexación orientada a conexión (TCP)

Socket identificado por **4 valores**: IP origen, Puerto origen, IP destino, Puerto destino. Cada conexión tiene su propio socket.

---

## 3. UDP (User Datagram Protocol)

```
| Source Port | Destination Port |
| UDP Length  | Checksum         |
|          Data                  |
```

- **No** orientado a conexión
- **No** confiable
- **No** control de flujo
- **No** reensambla mensajes
- **No** ACK
- Header mínimo (8 bytes)

---

## 4. TCP (Transmission Control Protocol)

### Header TCP

```
| Source Port    | Destination Port |
| Sequence Number                   |
| Acknowledgment Number             |
| HLEN | Flags   | Window           |
| Checksum       | Urgent Pointer   |
| Options        | Data...          |
```

**Flags**: URG, ACK, PSH, RST, SYN, FIN

### Características
- Orientado a conexión
- Confiable (ACK, retransmisión)
- Control de flujo (ventana)
- Control de congestión (AIMD)
- Orientado a **stream** (flujo de bytes, no mensajes)

---

## 5. TCP: Establecer conexión (3-way handshake)

```
Cliente                         Servidor
   |                               |  LISTEN
   |--- SYN=1, seq=x ------------>|
   |  SYN SENT                    |  SYN RCVD
   |<-- SYN=1, seq=y, ACK=x+1 ---|
   |  ESTAB                       |
   |--- ACK=y+1 ----------------->|
   |                               |  ESTAB
```

---

## 6. TCP: Acuse de recibo

TCP es un **flujo de bytes**. El ACK indica el **próximo byte esperado** (ACK acumulativo).

```
Origen: seq=90, 20B → seq=110, 30B → seq=140, 15B
Destino: ACK 140 → ACK 155
```

### Pérdida de segmentos
- Si se pierde un segmento, el receptor envía ACK del último byte recibido en orden
- El emisor retransmite al detectar **timeout** o **3 ACKs duplicados**
- El receptor puede almacenar segmentos fuera de orden y entregarlos cuando se complete el hueco

---

## 7. TCP: Control de flujo

El receptor informa al emisor cuánto espacio tiene en su buffer mediante el campo **Window** en el ACK.

```
Origen: seq=90, 120B
Destino: ACK 210, window=90    ← "solo puedo recibir 90 bytes más"
```

> [!note]
> Window es de 16 bits (máx 64 KB). Para redes modernas se usa **Window Scaling** (RFC 7323) que permite ventanas mucho mayores.

---

## 8. TCP: Cierre de conexión

```
Origen                          Destino
   |  ESTAB                       |  ESTAB
   |--- FIN=1, seq=x ------------>|
   |  FIN_WAIT_1                  |  CLOSE_WAIT
   |<-- ACK=x+1 ------------------|  (puede seguir enviando)
   |  FIN_WAIT_2                  |
   |<-- FIN=1, seq=y -------------|  LAST_ACK
   |  TIMED_WAIT                  |
   |--- ACK=y+1 ----------------->|  CLOSED
   |  (espera 2*MSL)             |
   |  CLOSED                      |
```

> [!important]
> El cierre es **asimétrico**: quien recibe el FIN puede seguir enviando datos (half-close). TIMED_WAIT espera 2x el tiempo máximo de vida del segmento.

---

## 9. TCP: Control de congestión (AIMD)

RFC 5681. El emisor ajusta su ventana de congestión (**cwnd**):

- **Additive Increase**: incrementa cwnd en 1 MSS por cada RTT
- **Multiplicative Decrease**: al detectar pérdida, reduce cwnd a la mitad

### Slow Start
- cwnd inicial = 1 MSS
- Se **duplica** cwnd cada RTT (crecimiento exponencial)
- Hasta alcanzar un umbral, luego pasa a AIMD (crecimiento lineal)

## 10. Transferencia confiable

### Stop & Wait
Enviar un paquete → esperar ACK → enviar siguiente. Simple pero ineficiente.

### Pipelining
Enviar múltiples paquetes sin esperar ACK individual. Mucho más eficiente.

### Mecanismos de confiabilidad
- **CRC/Checksum**: detectar errores de bits
- **ACK/NAK**: confirmar recepción
- **Números de secuencia**: detectar duplicados y ordenar
- **Timeout**: detectar pérdidas

## 11. SCTP (Stream Control Transmission Protocol)

RFC 4960. Diseñado para telefonía sobre IP.

| Característica | SCTP | TCP | UDP |
|---|---|---|---|
| Confiable | Sí | Sí | No |
| Control de flujo | Sí | Sí | No |
| Orientado a conexión | Sí | Sí | No |
| Orientado a **mensaje** | Sí | No | Sí |
| **Multi-homing** | Sí | No | No |
| **Multi-streaming** | Sí | No | No |
| Datos fuera de orden | Sí | No | Sí |
| Cookie anti-SYN flood | Sí | No | No |
| Heartbeat | Sí | No | No |

### Multi-homing
Origen y/o destino con **más de una IP**. Si falla una ruta, usa la otra.

### Multi-streaming
Múltiples flujos independientes dentro de una misma conexión. Resuelve el **Head-of-Line Blocking** de TCP.

### 4-way handshake (protegido)
```
INIT → INIT-ACK (cookie) → COOKIE-ECHO → COOKIE-ACK
```
El servidor **no reserva recursos** hasta recibir el COOKIE-ECHO (protección contra SYN flood).

### Por qué no se usa masivamente
- Compatibilidad limitada en SO y dispositivos
- Firewalls y NATs no lo reconocen
- HTTP/2 y HTTP/3 (QUIC) resuelven HOL de otra forma

## 12. NAT / NAPT

**NAPT** (Network Address Port Translation): permite que múltiples hosts con IP privada compartan una IP pública.

### SNAT (Source NAT)
```
Host interno: 192.168.1.2:900 → Destino: 200.23.54.11:80
Router traduce a: 24.16.14.132:770 → 200.23.54.11:80
```

El router mantiene una **tabla de traducción** con IP/puerto origen, destino y salida.

### DNAT (Destination NAT / Port Forwarding)
Redirige conexiones entrantes a un servidor interno:
```
Entrada: 24.16.14.2:80 → Redirigido a: 192.168.1.4:8080
```

Permite **balanceo de carga**: múltiples servidores internos atendidos por una única IP pública.

## 13. Firewalls

### Tipos

| Tipo | Nivel | Descripción |
|---|---|---|
| **Packet Filter** | Red/Transporte | Evalúa cada paquete IP contra reglas (IP, puerto, protocolo, interfaz) |
| **Circuit Level** | Sesión | Valida si un paquete pertenece a una sesión TCP válida (SYN/ACK) |
| **Application Layer** | Aplicación | Proxy que inspecciona contenido (filtrar URLs, cache, logs) |
| **Dynamic Packet Filter** | Red/Transporte | Modifica reglas dinámicamente (ej: permite respuesta UDP solo si hubo consulta previa) |

### Packet Filter
- Cada paquete se evalúa contra reglas
- Si no mapea con ninguna regla → **deny** (por defecto)
- Acciones: **allow** o **deny**
- Criterios: IP origen/destino, puerto, protocolo (TCP/UDP/ICMP), interfaz

### Circuit Level
Almacena estado de conexiones TCP: IPs, puertos, números de secuencia, estado de la conexión.

> [!note]
> Para UDP (sin conexión), los firewalls dinámicos permiten la respuesta solo si se detectó una consulta saliente previa.
