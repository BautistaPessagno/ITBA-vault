# Resumen Clase 05 - Red

Resumen orientado a resolver la **Guía 05 de ejercicios**.

---

## 1. Capa de red: servicios básicos

**Objetivo**: trasladar paquetes de un host a otro, que pueden estar en distintas redes.

### Servicios

| Servicio | Descripción |
|---|---|
| Encapsulamiento | El segmento/datagrama de transporte se encapsula en un paquete IP |
| Forwarding | Reenviar paquetes al siguiente salto según la tabla de ruteo |
| Routing | Determinar la ruta desde origen a destino (construir la tabla) |

### Servicios adicionales posibles
Entrega garantizada, demora mínima, orientado a conexión, entrega en orden, ancho de banda mínimo, integridad de datos, encriptación.

> [!note]
> IP **no ofrece** ninguno de estos servicios adicionales. Es un servicio **sin conexión, sin reconocimiento** (best effort).

## 2. Circuitos virtuales vs Datagramas

| Aspecto | Datagrama | Circuito virtual |
|---|---|---|
| Establecer conexión | No requerido | Requerido |
| Direccionamiento | ID de host origen y destino | Número de CV |
| Info de estado | No | Tabla con números de CV en cada router |
| Enrutamiento | Cada paquete ruta independiente | Todos los paquetes del CV misma ruta |
| Si falla un nodo | Se pierden algunos paquetes | Todos los CV que pasan por el nodo finalizan |
| Control de congestión | Complejo | Simple |
| Complejidad | En la capa de transporte | En la capa de red |

**IP usa datagramas** (conmutación de paquetes).

## 3. Direccionamiento IPv4

### Clases (hasta 1993)

| Clase | Rango primer octeto | Máscara default | Redes | Hosts por red |
|---|---|---|---|---|
| A | 1-126 | /8 | 126 | 16.777.214 |
| B | 128-191 | /16 | 16.384 | 65.534 |
| C | 192-223 | /24 | 2.097.152 | 254 |
| D | 224-239 | — | Multicast | — |
| E | 240-255 | — | Reservado | — |

### Direcciones IP reservadas

| Dirección | Uso |
|---|---|
| Host ID todo ceros | Identifica la **red** |
| Host ID todo unos | **Broadcast** de la red |
| `127.x.x.x` | **Loopback** (ej: `127.0.0.1`) |
| `10.x.x.x` | Red privada clase A (RFC 1918) |
| `172.16.0.0` - `172.31.255.255` | Red privada clase B (RFC 1918) |
| `192.168.x.x` | Red privada clase C (RFC 1918) |
| `169.254.x.x` | **Link-local** (RFC 6890) |

## 4. Tabla de ruteo

Cada host y router tiene una tabla con entradas:

```
Destination     Gateway         Mask              Interface
0.0.0.0         200.1.1.1       0.0.0.0           eth0       ← default
127.0.0.0       0.0.0.0         255.0.0.0         lo
200.1.1.0       0.0.0.0         255.255.255.0     eth0       ← red local
```

### Coincidencia del prefijo más largo (Longest Prefix Match)

Si una dirección coincide con múltiples entradas, se usa la que tiene el **prefijo más largo** (máscara más específica).

### Operación para obtener dirección de red

`Dirección de red = IP AND Máscara`

## 5. Subredes - VLSM (Variable Length Subnet Mask)

En 1993 se busca resolver:
- **Agotamiento** de direcciones IPv4
- **Crecimiento** de las tablas de ruteo

### Cálculo de subredes

Dada la red `192.168.80.0/24`, particionar en 4 subredes:

| Subred | Hosts necesarios | Bits de host | Máscara |
|---|---|---|---|
| Workers | 120 | 7 (2^7=128) | /25 |
| Robots | 58 | 6 (2^6=64) | /26 |
| Servers | 29 | 5 (2^5=32) | /27 |
| Guest | 14 | 4 (2^4=16) | /28 |

> [!important]
> **Siempre restar 2** del total: una dirección para la red y una para broadcast.
> Con /25: 128 - 2 = **126 hosts útiles**.

### Proceso paso a paso

1. Ordenar subredes de **mayor a menor** cantidad de hosts
2. Para cada subred: `2^n ≥ hosts + 2` → n bits de host → máscara = `/32-n`
3. Asignar rangos contiguos sin solapamiento

### Ejemplo completo

```
Red: 192.168.80.0/24

Workers /25: 192.168.80.0   - 192.168.80.127   (126 hosts)
Robots  /26: 192.168.80.128 - 192.168.80.191   (62 hosts)
Servers /27: 192.168.80.192 - 192.168.80.223   (30 hosts)
Guest   /28: 192.168.80.224 - 192.168.80.239   (14 hosts)
```

### Motivos para crear subredes
- **Topológicos**: hosts distantes, interconectar distintas capas físicas, filtrar tráfico
- **Organizacionales**: simplificar administración, mapear estructura, aislar tráfico

## 6. Superred - CIDR (Classless Inter-Domain Routing)

Agrupa múltiples redes contiguas en una sola entrada de tabla de ruteo.

### Ejemplo

```
172.16.0.0/14    16 = 0001 0000
172.20.0.0/14    20 = 0001 0100
172.24.0.0/14    24 = 0001 1000
172.28.0.0/14    28 = 0001 1100

Superred: 172.16.0.0/12  (coinciden los primeros 12 bits)
          máscara 255.240.0.0
```

### Motivos
- Optimización del enrutamiento
- Escalabilidad
- Mejor uso del espacio de direcciones
- Reducción de latencia

> [!note]
> Funciona porque desde 1993 la IANA asigna bloques jerárquicos a los RIR (registros regionales).

## 7. Paquete IPv4 (datagrama)

```
| Vers (4b) | HLen (4b) | ToS (8b) | Longitud total (16b)      |
| Identificación (16b)   | Flags (3b) | Offset de fragm. (13b) |
| TTL (8b) | Protocolo (8b) | Header Checksum (16b)            |
| Dirección origen (32b)                                        |
| Dirección destino (32b)                                       |
| Opciones (variable)     | Relleno                            |
| Datos (0 - 65.515 bytes)                                     |
```

Tamaño máximo: 2^16 = **65.536 bytes** (header + datos).
Header mínimo: **20 bytes** (sin opciones).

## 8. Fragmentación y reensamblado

Cuando un paquete es más grande que el **MTU** (Maximum Transmission Unit) del enlace, se fragmenta.

### Flags

| Flag | Significado |
|---|---|
| DF (Don't Fragment) | No fragmentar (si es necesario, descartar) |
| MF (More Fragments) | 1 = hay más fragmentos, 0 = último fragmento |

### Ejemplo

Paquete de 1700 bytes, MTU del enlace = 1500 bytes:

| Fragmento | Length | ID | MF | Offset |
|---|---|---|---|---|
| 1 | 1500 | 100 | 1 | 0 |
| 2 | 220 | 100 | 0 | 185 |

```
Fragmento 1: Header (20B) + Payload (1480B) = 1500B
Fragmento 2: Header (20B) + Payload (200B)  = 220B
Total payload: 1480 + 200 = 1680B (original: 1700 - 20 = 1680B) ✓
```

> [!important]
> El offset se mide en unidades de **8 bytes**: 1480 / 8 = 185.
> El reensamblado se hace en el **host destino**, no en routers intermedios.

## 9. DHCP (Dynamic Host Configuration Protocol)

Asignación **dinámica** de direcciones IP.

### Información que necesita una interfaz
- Dirección IP
- Máscara de red
- Dirección del Gateway
- Direcciones de servidores DNS

### Proceso DORA

```
Cliente                              Servidor DHCP
   |                                      |
   |--- DHCP DISCOVER (broadcast) ------->|  src: 0.0.0.0:68
   |    "¿Hay algún servidor DHCP?"       |  dst: 255.255.255.255:67
   |                                      |
   |<-- DHCP OFFER (broadcast/unicast) ---|  "Aquí tienes una IP"
   |    yiaddr: 200.1.2.5                 |  lifetime: 3600 secs
   |                                      |
   |--- DHCP REQUEST (broadcast) -------->|  "Voy a usar esa IP"
   |    yiaddr: 200.1.2.5                 |
   |                                      |
   |<-- DHCP ACK (broadcast/unicast) -----|  "OK, usala por ese tiempo"
   |    yiaddr: 200.1.2.5                 |
```

### Renovación (Renew)
El cliente envía un **DHCP Request** antes de que expire el lease para renovar.

### DHCP Relay Agent

Si el servidor DHCP está en **otra red**, un router con función de **Relay** reenvía los mensajes:

1. Cliente envía DISCOVER broadcast
2. Relay lo reenvía **unicast** al servidor DHCP
3. Servidor envía OFFER unicast al Relay
4. Relay lo reenvía **broadcast** en la red del cliente
5-9. Se repite para REQUEST/ACK

### DNS dinámico integrado con DHCP

El servidor DHCP puede actualizar automáticamente los registros DNS cuando asigna una IP.

```
# dhcp.conf
ddns-updates on;
ddns-update-style interim;
ddns-domainname "midominio.com";
```

## 10. NAT - SNAT (Source NAT)

Permite que múltiples hosts con **IP privada** compartan una **IP pública**.

### Funcionamiento

```
Host interno                Router (NAT)                  Internet
192.168.0.10:64132  →  200.1.25.134:64132  →  200.23.54.11:443
```

El router mantiene una **tabla de traducción**:

| IP Privada | Puerto Privado | IP Pública | Puerto Público |
|---|---|---|---|
| 192.168.0.10 | 64132 | 200.1.25.134 | 64132 |
| 192.168.0.13 | 12537 | 200.1.25.134 | 12537 |
| 192.168.0.24 | 64132 | 200.1.25.134 | 64133 |

> [!important]
> Campos modificados al aplicar SNAT: **dirección IP origen** y **header checksum**.

## 11. NAT - DNAT (Destination NAT / Port Forwarding)

Redirige conexiones entrantes a un servidor en la red interna.

### Solución 1: Configurar DNAT manualmente

```
Tabla DNAT:
IP Privada      Puerto Privado    Puerto Público
192.168.0.24    443               8080

Entrada:  200.23.54.11 → 200.1.230.29:8080
Router:   Traduce a → 192.168.0.24:443
```

### Solución 2: Configurar DNAT automáticamente

Protocolos **UPnP** (Universal Plug and Play) / **IGD** (Internet Gateway Device) permiten que las aplicaciones configuren el port forwarding automáticamente.

### Solución 3: Relay

Cuando dos dispositivos están **ambos detrás de NAT**, un servidor intermedio (Relay) con IP pública facilita la comunicación. Los dos clientes se conectan al relay, que mantiene una tabla con las IPs públicas de cada uno.

## 12. ICMP (Internet Control Message Protocol)

Protocolo de control y diagnóstico. Se encapsula directamente en IP (Protocolo 1).

```
| Type (8b) | Code (8b) | Checksum (16b) |
| Data (depende de tipo y código)         |
```

### Tipos principales

| Type | Mensaje | Uso |
|---|---|---|
| 0 | Echo Reply | Respuesta a ping |
| 3 | Destination Unreachable | Red/host/puerto inalcanzable |
| 5 | Redirect | Informar al host de una mejor ruta |
| 8 | Echo Request | Ping |
| 11 | Time Exceeded | TTL expirado (usado por traceroute) |
| 13/14 | Timestamp Request/Reply | Sincronización de reloj |

### ICMP Redirect

Si un router detecta que un paquete debería haber sido enviado a otro router en la misma red, envía un **ICMP Redirect** al host origen para que actualice su tabla de ruteo.

```
Host (192.168.10.6) envía paquete a 192.168.20.5
  → Sale por gateway 192.168.10.2
  → Router 192.168.10.2 reenvía a 192.168.10.1
  → Router 192.168.10.2 envía ICMP Redirect a Host:
    "Para llegar a 192.168.20.0/24, usá 192.168.10.1"

El host actualiza su tabla:
  Destination       Gateway          Interface
  192.168.20.0/24   192.168.10.1     eth0
```

## 13. Utilidades de networking

### Diagnóstico progresivo con ping

| Comando | Verifica |
|---|---|
| `ping 127.0.0.1` | Pila de networking y servicios de red habilitados |
| `ping IP_local` | Placa de red configurada |
| `ping host_mismo_segmento` | Placa, cable, switch y que el host remoto responde |
| `ping host_otro_segmento` | Router y tabla de ruteo configurados |
| `ping host_fuera_de_la_red` | Routers con salida a Internet funcionando |

### Traceroute

Muestra la ruta completa hacia un destino usando paquetes con **TTL incrementales**. Cada router que descarta el paquete por TTL=0 envía un ICMP Time Exceeded.

```bash
$ traceroute campus.itba.edu.ar
1  <1 ms  192.168.1.1
2  * * *  Request timed out
6  15 ms  200.89.161.129  (fibertel.com.ar)
...
17 159 ms 192.230.225.58  (itba.blackboard.com)
```

## 14. IPv6

### Comparación IPv4 vs IPv6

| Aspecto | IPv4 | IPv6 |
|---|---|---|
| Tamaño dirección | 32 bits | **128 bits** |
| Cantidad | ~4.300 millones | ~3.4 × 10^38 |
| Formato | `192.168.1.1/24` | `fe80::94db:946e:8d4e:129e/64` |
| Encabezado | Variable | **Fijo** |
| Fragmentación | Permitida | **No** permitida |
| Configuración | DHCP o manual | **Autoconfiguración** posible |
| IPSec | Opcional | Incorporado en diseño |
| RFC | 791 (1981) | 2460 (1998) → 8200 (2017) |

### Notación abreviada

```
Completa:   2001:0db8:0000:0000:0000:ff00:0042:8329
Sin ceros:  2001:db8:0:0:0:ff00:42:8329
Con ::      2001:db8::ff00:42:8329
```

> [!important]
> `::` solo puede usarse **una vez** en una dirección (reemplaza la secuencia más larga de grupos todo-ceros).

### Tipos de direcciones IPv6

| Tipo | Prefijo | Alcance |
|---|---|---|
| **Global Unicast** | `2000::/3` | Internet (equivalente a IP pública) |
| **Unique Local** | `FC00::/7` | Privada (equivalente a RFC 1918) |
| **Link-Local** | `FE80::/10` | Solo el enlace local (no se rutea) |

### Asignación del Interface ID (64 bits)

| Método | Descripción |
|---|---|
| **EUI-64** | Basado en MAC. En desuso por privacidad y seguridad |
| **RFC 7217** | Genera direcciones aleatorias pero **estables** por red |

EUI-64 inserta `FF:FE` en el medio de la MAC:
```
MAC: 02:1A:2B:3C:4D:5E
Interface ID: 021A:2BFF:FE3C:4D5E
Link-local: FE80::021A:2BFF:FE3C:4D5E
```

### NAT64: conectando IPv6 con IPv4

Permite que hosts **solo IPv6** se comuniquen con servidores **solo IPv4**:
- **DNS64**: traduce registros A a AAAA sintéticos con prefijo `64:ff9b::`
- **NAT64**: traduce los paquetes IPv6 a IPv4

## 15. Túneles

**Tunneling**: encapsular datos de un protocolo en los datos de otro protocolo de igual o mayor nivel.

### IP-en-IP

```
Red A (10.0.1.0/25)  ---  Internet  ---  Red B (10.0.1.128/25)
      R1 (24.10.11.12)              R2 (24.13.14.15)
```

```bash
# En R1:
$ ifconfig tunl0 10.0.1.1 pointopoint 24.13.14.15
$ route add -net 10.0.1.128 netmask 255.255.255.128 dev tunl0

# En R2:
$ ifconfig tunl0 10.0.1.254 pointopoint 24.10.11.12
$ route add -net 10.0.1.0 netmask 255.255.255.128 dev tunl0
```

El paquete original se encapsula dentro de otro paquete IP:
```
| IP Header externo (proto=4) | IP Header original (proto=1) | ICMP echo request |
   O: 24.10.11.12                 O: 10.0.1.2
   D: 24.13.14.15                 D: 10.0.1.130
```

> [!important]
> IP-en-IP **no ofrece confidencialidad ni integridad**. Para eso se necesita IPSec.

### Tipos de túneles (campo Protocolo en IP header)

| Valor | Protocolo |
|---|---|
| 1 | ICMP |
| 4 | **IP** (túnel IP-en-IP) |
| 6 | TCP |
| 17 | UDP |
| 41 | **IPv6** (túnel 6in4) |
| 89 | OSPF |

## 16. Seguridad e IPSec

### Triángulo CIA

| Pilar | Descripción | Ejemplos |
|---|---|---|
| **C**onfidencialidad | Solo accesible a autorizados | Cifrado, control de acceso |
| **I**ntegridad | No alterada sin autorización | Hashing, firmas digitales |
| **A** (Disponibilidad) | Accesible cuando se necesita | Redundancia, backups, anti-DDoS |

### IPSec

**Objetivo**: proveer servicios de seguridad para paquetes IP en capa de red.

Servicios: control de acceso, confidencialidad, autenticación, integridad.

### Modos de operación

| Aspecto | Modo Transporte | Modo Túnel |
|---|---|---|
| Protege | Solo el payload | **Todo** el paquete original (header + payload) |
| Header IP | Se mantiene el original | Se agrega un **nuevo** header IP |
| Uso típico | Host a host | Gateway a gateway (VPN) |

### Protocolos de seguridad

| Protocolo | Número | Confidencialidad | Integridad | Autenticación |
|---|---|---|---|---|
| **AH** (Authentication Header) | 51 | No | Sí | Sí |
| **ESP** (Encapsulating Security Payload) | 50 | **Sí** | Sí | Sí |

### Modo Transporte

```
AH:   | IP (proto=51) | AH Header | TCP | Payload |
      ✅ Integridad y autenticación
      ❌ No cifra datos (viajan en texto claro)

ESP:  | IP (proto=50) | ESP Header | TCP | Payload | ESP Trailer | ESP Auth |
      ✅ Confidencialidad, integridad y autenticación
```

### Modo Túnel

```
AH:   | IP nuevo (proto=51) | AH | IP original | TCP | Payload |
      ✅ Protege integridad incluyendo header IP original
      ❌ No cifra

ESP:  | IP nuevo (proto=50) | ESP Header | IP orig | TCP | Payload | ESP Trailer | ESP Auth |
      ✅ Cifra toda la comunicación (header IP original + datos)
      ✅ Protege confidencialidad, integridad y autenticidad
```

## 17. Firewalls e IPTables

### Evolución

```
1980: Packet filter
1990: Circuit level → Application layer
2000: Dynamic packet filter (stateful)
```

### IPTables - Cadenas

| Cadena | Cuándo actúa |
|---|---|
| PREROUTING | Antes del enrutamiento (modifica paquetes antes de rutear) |
| INPUT | Paquetes que **entran** al sistema y están dirigidos a él |
| FORWARD | Tráfico que **atraviesa** el sistema |
| OUTPUT | Paquetes **generados** por el sistema antes de salir |
| POSTROUTING | Después del enrutamiento |

### IPTables - Tablas

| Tabla | Uso |
|---|---|
| **filter** | Filtrado de paquetes (permitir, denegar, registrar) |
| **nat** | Traducción de direcciones (DNAT, SNAT, Masquerade) |
| **mangle** | Modificación avanzada de paquetes (ToS, TTL, marcado) |
| **raw** | Manipulación antes del seguimiento de conexiones |

### Comandos básicos

```bash
# Listar reglas de la tabla NAT
$ iptables -t nat -L

# Listar conexiones NAT activas
$ netstat-nat -n

# SNAT con MASQUERADE (IP dinámica)
$ iptables -t nat -A POSTROUTING -o eth1 -j MASQUERADE

# SNAT con IP fija
$ iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth1 -j SNAT --to 20.28.101.14

# SNAT limitando puertos
$ iptables -t nat -A POSTROUTING -p tcp -o eth1 -j SNAT --to 20.28.101.14:1-1023
```

### Ejemplo práctico completo

```
192.168.2.3 ──┐
192.168.2.2 ──┤── eth1 ─ [Host IPTables] ─ eth0 ── Internet
              │         192.168.2.1      24.232.138.143
```

```bash
#!/bin/bash
# Reenviar paquetes de eth1 (red interna) a eth0 (Internet)
iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT

# Habilitar SNAT con IP pública fija
iptables -t nat -A POSTROUTING -o eth0 -j SNAT --to-source 24.232.138.143

# No aceptar IP Spoofing
iptables -A INPUT -i eth0 -s 24.232.138.143/32 -j DROP
iptables -A INPUT -i eth0 -s 192.168.0.0/24 -j DROP
iptables -A INPUT -i eth0 -s loopback/8 -j DROP

# Aceptar tráfico de localhost
iptables -A INPUT -i lo -j ACCEPT

# DNAT para Web Server interno
iptables -t nat -A PREROUTING -d 24.232.138.143 -p tcp --dport 80 -j DNAT --to-destination 192.168.2.3
```
