e# Resumen Clase 09 - SSH

Resumen basado en las slides de SSH y el documento de **túneles dinámicos**.

## 1. Introducción a SSH

SSH es un **protocolo** pero también puede verse como:
- Una herramienta para **encriptar**
- Una aplicación **cliente/servidor**
- Una **interfaz de comandos**

### Servicios que ofrece

- **Autenticación**: verificar identidad de cliente y servidor
- **Encriptación**: los datos viajan cifrados (reemplazo seguro de telnet)
- **Integridad**: detecta si un mensaje fue alterado en tránsito

### SSH como reemplazo seguro

| Aplicación SSH | Reemplaza a |
|---|---|
| ssh | telnet, rlogin, rsh |
| scp | rcp |
| sftp | ftp |
| sshd | demonios de telnet, rlogin, rsh, ftp |

## 2. OpenSSH

### Componentes

| Componente | Función |
|---|---|
| `sshd` | Demonio que maneja conexiones entrantes (no usar con inetd) |
| `ssh` | Comando para login remoto o ejecución de comandos |
| `scp` | Copia segura de archivos |
| `sftp` | FTP seguro |
| `ssh-keygen` | Generador de claves públicas y privadas |

### Configuración (`/etc/ssh/sshd_config`)

```
Port 22
Protocol 2
ListenAddress 0.0.0.0
LoginGraceTime 120
PermitRootLogin no
StrictModes yes
```

Puerto por defecto: **22**

## 3. Ejemplos de uso

### Terminal remota
```bash
$ ssh pi@pampero.itba.edu.ar
Password: ******
# Interacción como con telnet, pero encriptada
$ logout
```

### Ejecución remota de un comando
```bash
$ ssh user@host rm /tmp -r
```

### Opciones principales de ssh

| Opción | Descripción |
|---|---|
| `-1` / `-2` | Forzar SSH versión 1 o 2 |
| `-C` | Comprimir datos |
| `-c blowfish\|3des\|des` | Elegir método de encriptación |
| `-v` | Información de depuración |
| `-4` / `-6` | Forzar IPv4 o IPv6 |
| `-p port` | Usar puerto distinto a 22 |
| `-N` | Solo conectar, no ejecutar comando remoto |
| `-E log_file` | Debug a archivo |

### Copia de archivos con scp
```bash
$ scp yo@casa.no-ip.info:*.pdf .
# Opciones adicionales:
# -q    Deshabilita porcentaje de progreso
# -r    Copia recursiva de directorios
```

### SFTP
```bash
$ sftp mgarbe@pampero.itba.edu.ar
sftp> lls          # listar archivos locales
sftp> lpwd         # directorio local actual
sftp> quit
# -B buffer_size   Buffer de transferencia
# -b batch_file    Lee comandos desde archivo
```

## 4. Port Forwarding - Local

SSH puede encriptar en forma transparente el flujo de datos de otra aplicación (**tunneling**).

### Sintaxis
```bash
$ ssh -L puerto_local:host_remoto:puerto_remoto servidor_SSH
```

- `puerto_local`: puerto del socket pasivo local
- `host_remoto`: host visible **desde el servidor SSH**
- `puerto_remoto`: puerto de la aplicación en el host remoto

### Ejemplo: acceder a un web server en red privada

```bash
# Paso 1: establecer túnel
$ ssh -L 2001:10.1.0.10:80 -l user sshserver

# Paso 2: usar el túnel
$ curl localhost:2001
```

El cliente SSH local lee el puerto 2001, encripta los datos y los envía al servidor SSH. El servidor los desencripta y los envía a `10.1.0.10:80`. Las respuestas vuelven por el mismo túnel.

> [!note]
> Para el web server, quien hizo el request es el **servidor SSH**, no el cliente original.

> [!important]
> Port forwarding funciona **solo con TCP**, no con protocolos basados en UDP (DNS, DHCP, NFS, NetBIOS).

### Gateway: compartir el túnel

Por defecto solo el host local puede usar el túnel. Para permitir que otros hosts de la red lo usen:

```bash
$ ssh -g -L 2001:webserver:80 -l user sshserver
# o equivalente:
$ ssh -L 0.0.0.0:2001:webserver:80 -l user sshserver
```

## 5. Port Forwarding - Remoto

Crea un socket pasivo en el **servidor SSH** que redirige al host local.

### Sintaxis
```bash
$ ssh -R puerto_remoto:host_local:puerto_local servidor_SSH
```

### Ejemplo: acceder a Postgres de casa desde ITBA

```bash
# Desde casa (192.168.1.3):
$ ssh -R 2001:192.168.1.2:5432 moss@pampero

# Desde pampero (ITBA), cualquier usuario puede conectarse:
$ psql -p 2001
```

El puerto 2001 de pampero se redirige al puerto 5432 del servidor Postgres en la red de casa.

## 6. Port Forwarding - Dinámico (SOCKS5)

Crea un proxy **SOCKS5** en el puerto local. Todo el tráfico enviado al proxy se encripta y sale por el servidor SSH.

### Sintaxis
```bash
$ ssh -D 9090 pampero.itba.edu.ar
```

### Uso con Chrome
```bash
$ google-chrome --proxy-server="socks5://localhost:9090"
```

### Aplicaciones
- Navegar con la **IP del servidor SSH** (ej: si está en USA, aparecés con IP de USA)
- Acceder a contenido restringido por región
- Bypass de firewalls

> [!note]
> Algunos servicios (Netflix, Disney+) filtran IPs de servidores conocidos y VPNs públicas. HBO funcionaba al momento de la prueba (2022).

### Configurar a nivel de SO
También se puede configurar el proxy SOCKS5 a nivel de sistema operativo en las preferencias de red.

## 7. Autenticación

### 7.1 Por claves (password)

Método más común. Controla usuario y contraseña con `/etc/passwd` o `/etc/shadow`.

```
# Deshabilitar en /etc/ssh/sshd_config:
PasswordAuthentication no
```

### 7.2 Por clave pública

Requiere un par de claves (pública + privada).

#### Generar claves en el cliente
```bash
$ ssh-keygen -d
# Genera: id_dsa (privada) e id_dsa.pub (pública)
```

#### Configurar en el servidor
```bash
$ cat id_dsa.pub >> ~/.ssh/authorized_keys
$ rm id_dsa.pub
```

#### sshd_config
```
PubkeyAuthentication yes
AuthorizedKeysFile .ssh/authorized_keys
```

#### Con PuTTY (Windows)
1. Usar **puttygen** para generar claves
2. En PuTTY: Connection > SSH > Auth → indicar archivo de clave privada
3. Agregar clave pública en el servidor igual que antes
4. Se puede importar claves generadas con OpenSSH

### 7.3 Autenticación del servidor

El **cliente** debe autenticar al servidor para evitar ataques Man-in-the-Middle.

```
Primera conexión:
1. Cliente: "Soy Moss"
2. Servidor envía su clave pública
3. Cliente guarda la clave (fingerprint)

Conexiones siguientes:
1. Cliente: "Soy Moss"
2. Servidor envía mensaje cifrado con su clave privada
3. Cliente verifica con la clave pública guardada
```

## 8. Modelo de capas SSH

```
| Aplicación SSH                    |
| Autenticación de usuario          |  SSH User Auth Protocol
| Manejador de Conexiones           |  SSH Connection Protocol
| Transporte (SSH TLP)              |  SSH Transport Layer Protocol
| TCP                               |
```

### Transporte (SSH Transport Layer Protocol)
- Provee **autenticación de servidor**, privacidad e integridad
- Opcionalmente puede **comprimir** datos
- Utiliza los servicios de TCP

### Autenticación (SSH User Authentication Protocol)
- Provee autenticación del **lado del cliente**

### Conexión (SSH Connection Protocol)
- **Multiplexar** el túnel seguro en distintos canales lógicos
- Canales posibles:
  - Sesiones de shell seguras
  - TCP port forwarding
  - Conexiones X11

```

    |                                    |
    |-------- conexión TCP ------------->|
    |                                    |
    |<-- intercambio string versión SSH->|
    |                                    |

    |    (incluye negociación de algo)   |
    |                                    |
    |<===== intercambio de datos SSH ===>|
    |                                    |
    |-------- fin de conexión TCP ------>|
```

## 10. Resumen de túneles SSH

| Tipo | Flag | Socket pasivo en | Redirige a | Uso típico |
|---|---|---|---|---|
| Local | `-L` | Cliente | Host remoto (vía SSH server) | Acceder a servicios internos |
| Remoto | `-R` | Servidor SSH | Host local (vía cliente) | Exponer servicio local |
| Dinámico | `-D` | Cliente (SOCKS5) | Cualquier destino (vía SSH server) | Proxy web, bypass firewall |
