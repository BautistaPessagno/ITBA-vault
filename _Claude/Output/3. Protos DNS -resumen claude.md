# Resumen Clase 03 - DNS

Resumen orientado a resolver la **Guía 03 de ejercicios**.

---

## 1. Resolución de Nombres

Proceso de traducir un **nombre de dominio** (www.ejemplo.com) a una **dirección IP** (192.0.2.1).

### Dominio vs Nombre de dominio vs FQDN

- **Dominio**: colección de computadoras accedidas con un nombre en común (ej: `itba.edu.ar`)
- **Hostname**: nombre propio de un host dentro del dominio (ej: `www`, `smtp`)
- **FQDN** (Fully Qualified Domain Name): hostname + dominio (ej: `smtp.it.itba.edu.ar`)

---

## 2. Cómo resolver un FQDN a IP

### Opción 1: `/etc/hosts`

Archivo local con pares IP-nombre. Se consulta **primero por defecto**.

```
127.0.0.1    localhost
192.168.2.2  printserver
```

### Opción 2: DNS Resolver (`/etc/resolv.conf`)

Si no se encuentra en `/etc/hosts`, el kernel consulta al DNS server configurado.

```
domain  itba.edu.ar
nameserver 192.168.2.1
nameserver 8.8.8.8
```

**Opciones de resolv.conf:**
- `nameserver`: IP de los servidores DNS (hasta 3)
- `domain`: dominio local por defecto (se agrega a hostnames sin punto)
- `search`: similar a domain pero acepta varios dominios

### Orden de consulta

Configurable en `/etc/host.conf`:
```
order hosts, bind     ← primero /etc/hosts, luego DNS
order bind, hosts     ← primero DNS, luego /etc/hosts
```

> [!important]
> El host mantiene en su **cache** los nombres que ha podido resolver.

## 3. DNS: Sistema jerárquico distribuido

DNS es un árbol invertido donde la raíz son los **root name servers**.

```
         .  (raíz)
       / | \
     com  ar  uk  ...
      |    |
     edu  com
      |
    itba
    / \
  www  it
```

### Tipos de servidores DNS

| Tipo | Función |
|---|---|
| **Recursivos** | Realizan la consulta completa en nombre del cliente |
| **Autorizados** | Contienen la información definitiva sobre dominios específicos |
| **Raíz** | Nivel más alto de la jerarquía (13 root name servers, operados por ICANN/IETF) |
| **TLD** | Responsables de `.com`, `.ar`, `.org`, etc. |
| **DNS local** | Cada ISP tiene uno; actúa como proxy y mantiene cache |

### Proceso de consulta (ejemplo: `smtp.it.itba.edu.ar`)

1. Cliente pregunta al **DNS local**
2. DNS local pregunta al **root server** → obtiene NS de `.ar`
3. Pregunta al NS de `.ar` → obtiene NS de `.edu.ar`
4. Pregunta al NS de `.edu.ar` → obtiene NS de `itba.edu.ar`
5. Pregunta al NS de `itba.edu.ar` → obtiene NS de `it.itba.edu.ar`
6. Pregunta al NS de `it.itba.edu.ar` → obtiene IP de `smtp.it.itba.edu.ar`

> [!important]
> Las consultas y respuestas DNS usan **UDP** (puerto 53).

### DNS Cache

- Los mapeos se almacenan en cache con un **TTL** (Time To Live)
- Los servidores generalmente cachean las direcciones de los TLD
- Los root servers **rara vez se consultan** en la práctica

---

## 4. Niveles de configuración de un servidor DNS

| Nivel | Descripción |
|---|---|
| **Resolver only** | Solo consulta a otros servidores |
| **Caching-only** | Almacena respuestas de otros servidores. No es autorizado |
| **Primary** | Fuente autorizada de una zona. Lee datos de archivos locales |
| **Secondary** | Copia de un primary. Puede responder con autoridad |

## 5. Registros DNS (Resource Records)

Formato: `(name, value, type, ttl)`

| Tipo | Name | Value |
|---|---|---|
| **A** | hostname | IPv4 |
| **AAAA** | hostname | IPv6 |
| **NS** | dominio | hostname del servidor DNS autorizado |
| **CNAME** | alias | nombre canónico |
| **MX** | dominio | servidor de mail (con prioridad) |
| **PTR** | IP invertida | hostname (DNS reverse) |
| **SOA** | Start of Authority | info autorizada de la zona |
| **SRV** | servicio | host:puerto de un servicio |
| **TXT** | dominio | texto libre (usado para SPF, DKIM, etc.) |

### Ejemplos

```
ejemplo.com.  IN  A      192.0.2.1
ejemplo.com.  IN  AAAA   2001:0db8::1
www.ejemplo.com. IN CNAME ejemplo.com.
ejemplo.com.  IN  MX  10  mail.ejemplo.com.
ejemplo.com.  IN  MX  20  backupmail.ejemplo.com.
ejemplo.com.  IN  NS   ns1.ejemplo.com.
ejemplo.com.  IN  TXT  "v=spf1 include:_spf.ejemplo.com ~all"
```

> [!note]
> El número en MX es la **prioridad** (menor = mayor prioridad). Si el servidor principal no responde, se intenta el de backup.

## 6. DNS Reverse

Para resolver IP → nombre se usa un árbol especial bajo `in-addr.arpa`:

```
host 157.92.27.21
→ 21.27.92.157.in-addr.arpa → dc.uba.ar
```

## 7. Configuración de zona DNS (ejemplo)

```
$TTL 86400
$ORIGIN example.com.
@  IN  SOA  ns1.example.com. hostmaster.example.com. (
     2024031201  ; Serial
     3600        ; Refresh
     600         ; Retry
     1w          ; Expire
     3h )        ; Minimum TTL

@     IN  NS   ns1.example.com.
@     IN  NS   ns2.example.com.
ns1   IN  A    192.168.0.1
www   IN  A    192.168.0.3
mail  IN  A    204.13.248.106
smtp  IN  CNAME mail.example.com.
@     IN  MX 10 mail.example.com.
@     IN  TXT "v=spf1 mx -all"
```

## 8. Utilidades DNS

### `host`
```bash
host www.itba.edu.ar        # nombre → IP
host 157.92.27.21           # IP → nombre (reverse)
```

### `dig`
```bash
dig www.itba.edu.ar                    # consulta completa
dig www.itba.edu.ar +noall +answer     # solo respuesta
dig host MX +noall +answer             # registros MX
dig -x 13.227.69.6                     # reverse DNS
dig host +trace                        # traza completa
```

### `nslookup`
```bash
nslookup www.itba.edu.ar              # consulta directa
nslookup                              # modo interactivo
> set type=NS
> itba.edu.ar
```

### `whois`
Para obtener información sobre el responsable de un dominio.

## 9. Conceptos avanzados

### Split-Horizon
Un mismo nombre se resuelve con **distinta IP** según el origen de la consulta (ej: IP privada desde adentro, IP pública desde afuera).

### DNS Dinámico (DDNS)
RFC 2136. Permite actualizar registros DNS dinámicamente. Útil para usuarios con IP dinámica (ej: no-ip.com).

### DNS Spoofing
Lograr que un registro DNS apunte a una IP falsa. Métodos:
- **Respuesta sin pregunta**: se verifica con ID de transacción
- **DNS Sniffer**: interceptar la consulta y responder antes que el servidor real
- **Cache Poisoning**: envenenar la cache de un servidor DNS con registros falsos
