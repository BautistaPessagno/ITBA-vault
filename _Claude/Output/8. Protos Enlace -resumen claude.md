# Resumen Clase 07 - Enlace

Resumen orientado a resolver la **Guía 07 de ejercicios**.

---

## 1. Servicios de capa de enlace

Servicio básico: **mover paquetes** desde un nodo al nodo adyacente sobre un enlace de comunicación.

| Servicio | Descripción |
|---|---|
| Encapsulamiento | Agrega header y trailer a los datos de red |
| Acceso al medio | Coordina el acceso al canal compartido |
| Comunicación confiable | Entrega garantizada (opcional) |
| Control de flujo | Evita saturar al receptor |
| Detección de errores | CRC, checksum |
| Corrección de errores | FEC (Forward Error Correction) |
| Half-duplex / Full-duplex | Dirección de la comunicación |

---

## 2. Tipos de comunicación a nivel de enlace

| Tipo | Uso | Ejemplo |
|---|---|---|
| Punto a punto | WAN | SLIP, PPP |
| Broadcast | LAN | Ethernet, Wi-Fi |

---

## 3. Protocolos punto a punto

### SLIP (RFC 1055, 1988)

- Extremadamente simple
- Encapsula datagramas IP sobre líneas seriales
- Delimitador: `0xC0`
- Escape: `0xDB` seguido de `0xDC` (para `0xC0`) o `0xDD` (para `0xDB`)

### PPP (RFC 1661, 1994)

Sucesor de SLIP. Mejoras:
- Soporta **múltiples protocolos** (no solo IP)
- **Detección de errores**
- **Autenticación** (PAP, CHAP)
- Notificación de direcciones
- Negociación de opciones
- Medición de calidad del enlace

## 4. Redes broadcast - Protocolos de acceso múltiple

Un canal compartido genera posibilidad de **colisión** (dos o más señales al mismo tiempo).

### Clasificación

```
Protocolos de acceso múltiple
├── Acceso canalizado (particionamiento)
│   ├── FDMA
│   ├── TDMA
│   └── CDMA
├── Acceso por turnos (controlado)
│   ├── Polling
│   └── Token passing
└── Acceso aleatorio
    ├── ALOHA puro
    ├── CSMA (1-persistent, non-persistent, p-persistent)
    ├── CSMA/CD (Collision Detection)
    └── CSMA/CA (Collision Avoidance)
```

---

## 5. Particionamiento del canal

- **FDMA**: cada estación usa una frecuencia diferente
- **TDMA**: cada estación usa un slot de tiempo diferente
- **CDMA**: cada estación usa un código diferente (multiplexación por código)

---

## 6. Protocolos por turnos

### Polling
- Un nodo **master** invita a cada nodo a transmitir por turnos
- Pro: no hay colisiones
- Contra: overhead de polling, latencia, **único punto de falla** (master)

### Token Ring
- Un **token** circula por el anillo
- Solo el nodo que tiene el token puede transmitir
- Pro: acceso equitativo, sin colisiones
- Contra: overhead del token, latencia, un nodo caído puede romper el anillo

---

## 7. Protocolos de acceso aleatorio

### ALOHA puro
- Cuando un nodo quiere transmitir: **transmite**
- Si hay colisión: espera un **retardo aleatorio** y reintenta
- Eficiencia máxima teórica: **18%**

### CSMA (Carrier Sense Multiple Access)
Escuchar antes de transmitir ("si alguien está hablando, no hablo").

| Variante | Comportamiento si canal ocupado |
|---|---|
| **1-Persistent** | Censado continuo, transmite apenas se libera |
| **Non-Persistent** | Espera un tiempo aleatorio, luego vuelve a censar |
| **p-Persistent** | Espera un time-slot, transmite con probabilidad p |

### CSMA/CD (Collision Detection)
- Usado en **Ethernet cableada**
- Detecta colisión **mientras transmite**
- Al detectar colisión: deja de transmitir inmediatamente
- Espera un tiempo aleatorio (Binary Exponential Backoff) y reintenta

### CSMA/CA (Collision Avoidance)
- Usado en **Wi-Fi** (802.11)
- No puede detectar colisiones mientras transmite
- Usa **RTS/CTS** (Request to Send / Clear to Send) para reservar el canal

## 8. Ethernet

El protocolo más usado en LANs cableadas. Muy económico y simple.

### Velocidades
10 Mbps → 100 Mbps → 1 Gbps → 10 Gbps

### Topología de bus (con hub)
- Todos los hosts en la misma línea
- Gran posibilidad de colisiones
- Si la red crece, se divide en **segmentos** (dominios de colisión)

### Topología de estrella (con switch)
- Cada host se conecta a un **switch**
- El switch dirige los datos por el puerto al que está conectado el host destino
- Puede **encolar** tramas
- Se basa en **MAC address**
- Se deben evitar los ciclos (Spanning Tree Protocol)

> [!important]
> Un **hub** opera en capa 1 (repite la señal a todos los puertos). Un **switch** opera en **capa 2** (usa direcciones MAC para enviar al puerto correcto). Un **router** opera en capa 3 (usa direcciones IP).

---

## 9. MAC Address

Dirección física de 6 bytes (48 bits), asignada a cada NIC.

```
Formato: XX:XX:XX:YY:YY:YY
         ─────────  ─────────
         OUI (3B)   Serial (3B)
```

### Bits especiales del primer octeto

| Bit | Valor 0 | Valor 1 |
|---|---|---|
| b0 | **Unicast** | **Multicast** |
| b1 | **UAA** (Universally Administered) | **LAA** (Locally Administered) |

- **Broadcast**: `FF:FF:FF:FF:FF:FF`
- El OUI identifica al fabricante (IEEE asigna los OUI)

> [!note]
> El comando `ifconfig` permite cambiar temporalmente la MAC de una interfaz. Si dos hosts tienen la misma MAC en la misma red, se produce un conflicto.

---

## 10. Trama Ethernet

```
| Preámbulo (7B) | Delimitador (1B) | MAC destino (6B) | MAC origen (6B) | Tipo (2B) | Datos | CRC (4B) |
```

| Campo | Descripción |
|---|---|
| Preámbulo | 7 bytes con patrón `10101010` |
| Delimitador | 1 byte: `10101011` |
| MAC destino | Si no es la MAC del receptor ni broadcast, se ignora la trama |
| Tipo | Código del protocolo encapsulado (`0x0800` = IP, `0x0806` = ARP, `0x8035` = RARP) |
| Datos | Longitud mínima y máxima según velocidad |
| CRC | Si detecta errores, se ignora la trama |

### Tipos de protocolo encapsulado

| Tipo | Protocolo | Tamaño datos |
|---|---|---|
| `0x0800` | Datagrama IP | variable |
| `0x0806` | ARP request/reply | 28 + 10 PAD |
| `0x8035` | RARP request/reply | 28 + 10 PAD |

## 11. ARP (Address Resolution Protocol)

Dado un **número IP**, necesita conocer la **dirección MAC** correspondiente.

### Funcionamiento

1. **ARP Request**: se envía en **broadcast** (`FF:FF:FF:FF:FF:FF`)
   - "¿Quién tiene el IP X.X.X.X?"
   - Target MAC: `00:00:00:00:00:00`

2. **ARP Reply**: se envía en **unicast** al solicitante
   - "Yo tengo el IP X.X.X.X, mi MAC es YY:YY:YY:YY:YY:YY"

### Tabla ARP

Cada host mantiene una tabla con la relación IP ↔ MAC.

```bash
# Ver tabla ARP
$ arp -a
# Internet Address    Physical Address    Type
# 192.168.2.1         00-03-0a-00-d8-d0   dynamic
# 192.168.2.4         00-00-21-fe-77-03   dynamic

# Agregar entrada estática
$ arp -s 192.168.2.99 00-00-21-fe-77-03
```

> [!important]
> Las entradas **dynamic** se borran después de un timeout. Las **static** persisten hasta ser eliminadas manualmente.

## 12. ARP entre dos redes distintas (flujo completo)

Escenario: Host A (`192.168.2.2`) envía un paquete IP a Host B (`10.2.0.2`). Tablas ARP vacías.

```
Red 192.168.2.0/24          Red 10.2.0.0/16
A (192.168.2.2) ─── Router (192.168.2.1 / 10.2.0.1) ─── B (10.2.0.2)
```

### Paso a paso

1. A examina su tabla de ruteo → gateway para llegar a B es `192.168.2.1`
2. A envía **ARP Request** broadcast: "¿Quién tiene `192.168.2.1`?"
3. El router envía **ARP Reply** unicast: "Yo, mi MAC es MAC_Router"
4. A envía **paquete IP** a MAC_Router con destino IP `10.2.0.2`
5. El router examina su tabla de ruteo → B está en red `10.2.0.0/16`
6. El router envía **ARP Request** broadcast en red 10.2.0.0: "¿Quién tiene `10.2.0.2`?"
7. B envía **ARP Reply** unicast al router: "Yo, mi MAC es MAC_B"
8. El router envía el **paquete IP** a MAC_B con destino IP `10.2.0.2`

> [!important]
> En el paso 4, la trama Ethernet tiene `MAC destino = MAC_Router` y `MAC origen = MAC_A`, pero el paquete IP mantiene `IP origen = 192.168.2.2` y `IP destino = 10.2.0.2`. Las MACs cambian en cada salto, las IPs no.

### Paquetes ARP totales: **4** (2 requests + 2 replies)

## 13. Tipos de ARP

| Tipo | Uso |
|---|---|
| **ARP** | Conoce IP, necesita MAC (RFC 826) |
| **RARP** | Conoce MAC, necesita IP (diskless workstation) (RFC 903) |
| **InARP** | Conoce MAC, necesita IP del otro host |
| **Proxy ARP** | Un router responde ARP requests en nombre de hosts en una red oculta |

### Proxy ARP
Si el host A solicita la MAC de un host C que está en una **red oculta**, el router responde con **su propia MAC**. Así la relación IP ↔ MAC no es 1 a 1.

---

## 14. ARP Spoofing

ARP **no contempla autenticación**. Cualquiera puede responder un ARP Request, asociando un IP con una MAC falsa.

### Ataques posibles

- **Man-in-the-Middle**: el atacante se pone "en el medio" de la comunicación
- **Denial of Service**: el atacante asocia IPs de la red con MACs inexistentes
- **Session Hijacking**: el atacante roba sesiones TCP

### Mecanismo
El atacante envía **ARP Reply periódicos** con las IPs conocidas pero su propia MAC. Los hosts actualizan sus tablas ARP con la MAC del atacante.

### Herramientas
Arpspoof, Arpoison, Cain & Abel, Ettercap

### Usos legales de ARP Spoofing
- Redireccionar equipos no registrados a una página de registro
- Acceso a Internet en hoteles
- Implementar **redundancia** en servicios de red

### Defensas

| Defensa | Descripción |
|---|---|
| Entradas ARP estáticas | Agregar manualmente las asociaciones críticas |
| DHCP Snooping | Dispositivos Cisco, Allied Telesis (validan ARP con DHCP) |
| Arpwatch | Programa Unix que monitorea respuestas ARP y avisa al admin si cambian |
| RARP Request | Si hay más de una respuesta, puede ser un ataque |
