### Listado Incompleto
![](Attachments/Pasted%20image%2020260521204054.png)
http://pubs.opengroup.org/onlinepubs/009695399/functions/getsockopt.html
SO_RCVLOWATSets the minimum number of bytes to process for socket input operations. The default value for SO_RCVLOWAT is 1. If SO_RCVLOWAT is set to a larger value, blocking receive calls normally wait until they have received the smaller of the low water mark value or the requested amount. (They may return less than the low water mark if an error occurs, a signal is caught, or the type of data next in the receive queue is different from that returned; for example, out-of-band data.) This option takes an int value. Note that not all implementations allow this option to be set.

SO_RCVTIMEO Sets the timeout value that specifies the maximum amount of time an input function waits until it completes. It accepts a timeval structure with the number of seconds and microseconds specifying the limit on how long to wait for an input operation to complete. If a receive operation has blocked for this much time without receiving additional data, it shall return with a partial count or errno set to [EAGAIN] or [EWOULDBLOCK] if no data is received. The default for this option is zero, which indicates that a receive operation shall not time out. This option takes a timeval structure. Note that not all implementations allow this option to be set.

### manejar el comportamiento
![](Attachments/Pasted%20image%2020260521205654.png)
sigaction se usa para cambiar el comportamiento default cuando nuestro proceso recibe una señal

Si act no es NULL, la nueva acción para signum es determinada por act. Si oldact no es NULL, la acción previa se guarda en oldact (por si nos interesa modificar el comportamiento solo una vez y luego volver a restaurar la acción por defecto).
Si act es NULL no se cambia la acción actual. Sólo es útil si se pasa algo distinto de NULL en oldact (actúa como una consulta)

Sa_handler: si es SIG_IGN la señal es ignorada, SIG_DFl la señal toma su comportamiento por defecto, Si es una función recibirá como parámetro la señal que la disparó.
Algunas implementaciones incluyen 
             void     	(*sa_sigaction)(int, siginfo_t *, void *);
(pero es sa_handler o sa_sigaction, no ambas

sa_mask: señales que se van a bloquear mientras se ejecuta la función sa_handler. La idea es que la función que maneja la señal no sea interrumpida por otra señal.

sa_flags: para modificar el comportamiento de signum, p.e SA_RESETHAND para que luego de ejecutar nuestra función vuelva al comportamiento default.

para más detalles de sa_flags: https://www.gnu.org/software/libc/manual/html_node/Flags-for-Sigaction.html

para una explicación detallada de sigaction ver http://man7.org/linux/man-pages/man2/sigaction.2.html

### sockets no bloqueantes
![](Attachments/Pasted%20image%2020260521210017.png)
The O_NONBLOCK doesn't provide any notification to the user process that a fd is ready for read(2)or write(2) -- instead, it changes the behavior of read(2) and write(2) and similar calls to return immediately if the file descriptor isn't ready for reading or writing. O_NONBLOCK is typically used in conjunction with select(2) or poll(2) or similar calls to guarantee that the main loop of a client or server won't block on one specific peer, and thus starve all its peers.

O_ASYNC flag (which is usually set in open(2) or fcntl(2)) for a file descriptor, which will ask the kernel to send SIGIO or SIGPOLL to the process when the file descriptor is ready for IO.
