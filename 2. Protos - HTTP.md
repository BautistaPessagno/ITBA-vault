# HTTP
previo a eso se usaba el FTP donde la persona tenia que acceder a otro sitio FTP y descragar el/los textos deseados

hipertexto surge de que se penso com un grafo. basado en archivos ya creados y de texto
mecanismo request -response
no mantiene estado (no establece una sesión)
orientado a linea de comando

el modo promiscuo hace que se levante todo el trafico que pasa

el HTTP es un protocolo de texto
Al ser texto el tamaño es variable
El uso de almacenamiento es muy importante
para saber el final de un texto se pasa el  \r\n para indicar el final de linea 

## Transmission Control Protocol [[TCP]]
es un protocolo binario
la transición de los datos es "big endian" ya que en memoria se aplica el little endian
se pasa el destination, el source, el type 

## HTTP 1.0 (1996)
browser friendly
comandos como GET, POST, HEAD
ambos GET y POST piden un recurso, HEAD solo pide la información de dicho recurso
solo se permitia usar ASCII standar

![[Pasted image 20260305194701.png]]
tambien da un codigo de estado como el 200, 404 entre otros y luego la informacion 

## HTTP 1.1 (1999)
metodos PUT, DELETE, TRACE, OPTIONS
Negociación de contenido
- soporte a distintos idiomas y contenidos
Soporte de cache
- se guarda información en la cache para no volver a pedir lo mismo
- Si el recurso ya lo tiene no se hace la request (a veces)
Conexiones persistentes
 - el canal de comunicación se mantiene abierto

![[Pasted image 20260305195446.png]]

## HTTP/2
protocolo binario no de texto
compresión de headers
multiplexación de recursos
server push
http://www.http2demo.io/
mucho mas rapido que HTTP 1
...

HTTP/2 exige seguridad

## HTTP/3
protocolo [[QUIC]] como "transporte"
menor latencia
multiplexacion mejorada
...

mas liviano que TCP pero no pierde seguridad

# Proxy Servers

![[Pasted image 20260305213238.png]]

# Cache
## max-age
con cache-control: max-age hace que lo guarde por un cierto tiempo en la cache. luego de ese tiempo lo libera
## last modify
se pasa last-modify y un Etag el cual es un id
recien cuando el recurso cambia le doy un tag nuevo
el proxy lo pide de forma condicional (si matchea el Etag o las fechas marcan que se modifico). si se modifico el server le pasa el nuevo recurso sino le pasa un 304 indicando que no se modifico
si bien siempre consulta al server en este caso solo se pasa el header sin datos

>[!tip]
se pueden usar ambos
