# Aplicaciones de Red

Se debe poder identificar los procesos
cada host se identifica por IP
muchos procesos corriendo en un host
cada proceso se identifica con un puerto


**A nivel de aplicación se debe definir:**
- Tipos de mensaje que se intercambia
- sintaxis de los mensajes
- semántica de los mensajes
- reacción frente a errores

## Interfaces de protocolo de transporte
el estandar TCP/IP sugiere que las API contemplen las sigiuentes operaciones basicas
- reservar recursos locales para la comunicacion
- especificar endpoints origen y destino
- iniciar conexion cliente
- enviar datagrama cliente
- esperar una conexion servidor
- enviar y recibir datos
- poder determinar cuando arriba informacion
- generar datos urgentes
- manejo el arribo de datos urgentes

cada uno lo implementa como quiere (**SOCKET API**, WINDOWS SOCKET, TLI)


## Sockets: conceptos basicos

El servidor debe estar en ejecuccion ANTES de que el cliente intente conectarse
El servidor debe tener un socket abierto, por el cual recibir y enviar mensajes
Los clientes necesitan un socket
Los cluentes necesitan conocer IP y numero de puerto del socket del servidor

## Aplicaciones de red: sockets
![[Pasted image 20260514192314.png]]
Un socket es una abstracción a través de la cual una aplicación puede enviar y recibir datos. Un socket permite a una aplicación “conectarse” a la red y comunicarse con otras aplicaciones que están conectadas a la misma red. Aplicación escrita por una aplicación en un host puede ser leída por una aplicación en el mismo u otro host y viceversa.

ejemplo el servidor DNS escucha tanto TCP como UDP en el mismo puerto

## Socket API
Un proceso que necesita realizar operaciones de E/S utiliza el system call open que crea un file descriptor, el cual usa para acceder al archivo. El S.O. implementa file descriptors como un vector de punteros a estructuras de datos.
![[Pasted image 20260514192550.png]]
La API de sockets agrega una nueva abstracción para las comunicaciones en red, el socket. Al igual que con los archivos, cada socket es identificado por un handle y la información relacionada es almacenada en la tabla de file descriptors.

## Socket API: ejemplo TCP
![[Pasted image 20260514193156.png]]
Analogía con la telefonía celular:
socket: tener un teléfono para poder usarlo
- con bind simplemente se dice en que puerto quiere escuchar
- bind: informarle al resto de las personas nuestro número de teléfono (publicarlo). Pero tenerlo en “modo avión”
- listen: activar el teléfono (sacarlo de modo avión)
- connect: conocer el teléfono del otro y marcarlo
- accept: similar a un caller ID. La diferencia es que con sockets el ID se obtiene una vez aceptada la conexión.
- send,recv: hablar y escuchar
- close: colgar

## Resolución de nombres

![[Pasted image 20260514195748.png]]
Ver programa de ejemplo getaddrinfo.c
La función getaddrinfo es sincrónica, existe una versión asincrónica llamada getaddrinfo_a 
(https://linux.die.net/man/3/getaddrinfo_a)

![[Pasted image 20260514201558.png]]
Ver programa getaddrinfo,c

ai_flags: Es un conjunto de indicadores que se utilizan para personalizar el comportamiento de la función getaddrinfo()). Algunos de los indicadores comunes incluyen AI_PASSIVE (para indicar que la dirección será utilizada para un socket pasivo) y AI_CANONNAME (para solicitar un nombre canónico para el host).
ai_family: Es el tipo de familia de direcciones. Esto puede ser AF_INET para direcciones IPv4, AF_INET6 para direcciones IPv6, o AF_UNSPEC para cualquier familia de direcciones.
ai_socktype: Es el tipo de socket, como SOCK_STREAM para un socket de flujo TCP o SOCK_DGRAM para un socket de datagrama UDP.
ai_protocol: Es el protocolo a utilizar, como IPPROTO_TCP para TCP o IPPROTO_UDP para UDP. Puede ser 0 si se deja al sistema seleccionar el protocolo adecuado.
ai_addrlen: Es la longitud en bytes de la dirección almacenada en ai_addr.
ai_addr: Es un puntero a una estructura sockaddr que contiene la dirección de red. La estructura sockaddr se utiliza para representar direcciones de sockets, pero debido a que getaddrinfo() es una función genérica, el tipo exacto de la estructura (como sockaddr_in para IPv4 o sockaddr_in6 para IPv6) no se conoce de antemano, por lo que se utiliza un puntero a sockaddr aquí.
ai_canonname: Es un puntero a una cadena que contiene el nombre canónico del host. Este campo puede ser NULL si no se proporciona un nombre canónico.
ai_next: Es un puntero al siguiente elemento en la lista de estructuras addrinfo. Esto es útil cuando getaddrinfo() devuelve múltiples resultados, como en el caso de resolución de nombres de host con múltiples direcciones IP asociadas.
